# Implementation Plan: per-user-medications

Spec: [SPEC-per-user-medications.md](../../SPEC-per-user-medications.md) · Map: [CAPABILITY-MAP.md](../../CAPABILITY-MAP.md) (initiative multi-user) · Tasks: [todo.md](todo.md) · Previous: [accounts](../accounts/plan.md)

## Overview

This module gives every medication an owner and scopes every reader of the list to the signed-in user: the medication routes, drug pages, prices and costs, alternatives' "taken for", the interaction checks and the digest page flag. The weekly digest runner keeps an explicit `listAllActive()` until `per-user-digest`.

## Architecture Decisions

- **Scoped repository.** `createMedicationsRepository(db).forUser(userId)` returns today's API, with `user_id` in every query. Readers take that scoped repository (or a `userId`) per request, so a reader can't forget the filter.
- **Services take the user per call**, as `service(userId)` or `method(..., userId)`, depending on each service's shape. Routes pass `requireUser(event).id`.
- **Test helper** (`src/server/tests/test-users.ts`): it seeds Alice and Bob in the test database, and provides an h3 middleware that sets `event.context.user` from an `x-test-user` header. Route specs keep calling handlers directly, without the cookie flow.
- **Migration 0008:** generated by drizzle-kit, with `DELETE FROM "medications";` added at the top before it's ever applied.

## Dependency Graph

```
1 schema + migration ── 2 scoped repository ── 3 test helper + medication routes ── 4 other readers (drug page, prices, alternatives, interactions, digest) ── 5 e2e, migration on dev copy, docs, coverage
```

## Risks and Mitigations

| Risk                                                    | Impact | Mitigation                                                                                                 |
| ------------------------------------------------------- | ------ | ---------------------------------------------------------------------------------------------------------- |
| A reader left unscoped leaks another user's list        | High   | Only `forUser` and the named `listAllActive` exist; grep for `listAllActive` callers; two-user route tests |
| Migration applied with rows present fails on `NOT NULL` | Med    | `DELETE` first in 0008; applied to a copy of the dev database before anything else                         |
| Many test files to update for the new signatures        | Med    | One test helper; mechanical edits; the full suites run at each checkpoint                                  |
